## THE ANSWER TO "IT'S MISSING SOMETHING" — three absent mechanisms

### 1. The bot has no runtime truth loop with the exchange  [CONFIRMED]
Everything that compares ledger ↔ Kraken positions runs **once, at startup**:

- `verify_open_stops` — only caller is `app.py:350` (boot). Nothing at runtime ever calls
  `OpenPositions` except the T/P flatten.
- A protective stop that **fires while the bot is running is never noticed**: `status='closed'`
  transitions exist only in `_flatten_all` and `verify_open_stops`. `_stop_exit_pnl_json` is
  reached only from the restart reconcile. After an intraday stop-out the rows stay 'open',
  the day-realized readout doesn't move, counts/margin displays are phantoms, and the chain's
  resting bid keeps working the falling market.
- Stop events are **cluster exits**: all rungs in a chain share one stop price
  (LTC 27×@41.14; ADA 17@0.1475+6@0.14821; SUI 22@0.6846+1@0.6749) — so the phantom-state
  blast radius is the whole chain at once, not one rung.
- A force-liquidation or manual close leaves the stop RESTING with no position behind it;
  when price later hits it, it sells naked → opens a short on the :BTNL book — the exact
  catastrophe class the code exists to prevent (reconciler agent C1, verified).
- Worse, `_reprotect_naked_open` (executor.py:509) consults only OpenOrders, never
  OpenPositions — it can re-arm a stop for a position that died minutes earlier,
  *manufacturing* the orphan stop (C2, verified).

**Fix shape:** run PASS 1 of `verify_open_stops` (or a cheap OpenPositions sweep) on a timer
(per-poll or hourly); detect executed stops in the same sweep (query stop_txids of open rows);
have `_reprotect_naked_open` confirm the position exists before resting.

### 2. Nothing watches the account itself: margin level + rollover drag  [CONFIRMED]
- `broker.trade_balance_full()` returns Kraken's margin level; the ONLY consumers are display
  (app.py:290, ui.py:763). No executor logic reads it. The seeder/ladder grows notional with
  no awareness of ml; Kraken margin-calls at 80% and force-liquidates at 40% — bypassing every
  stop, in an order the ledger can't predict (and per #1, the ledger wouldn't notice). Nothing
  even alerts on descent. Not a rail — it protects against the *exchange* seizing the book.
- Rollover: Kraken charges 0.01–0.05% of notional per 4h (locked at execution; most alts 0.02%).
  Current book: $296 notional on $93 equity ≈ **$0.36–0.89/day ≈ 0.4–1.0% of equity per day**,
  ~11–30%/month, growing as the seeder stacks. It is accounted **nowhere**: not in sizing, not
  in the T/P target, explicitly not in P&L (executor.py:1211 admits it), not in any display.
  Fee bleed is indistinguishable from market losses on every readout.
- Interaction (executor agent M1, verified): `tp_baseline` never ratchets down. Armed at 92.86;
  after any drawdown the +20% target recedes while rollover bleeds ~0.4–1%/day — the
  stack→harvest→restack cycle silently degrades to "hold leveraged longs forever, paying
  rollover, until stops or liquidation." No re-arm mechanism, no "distance to target" surface.

**Fix shape:** (a) poll ml each cycle → pause *seeding only* + loud alert below an operator
threshold (e.g. 150%) — entries on signal stay untouched (no-blockers preserved);
(b) pull rollover ledger entries via QueryLedgers into a fees-paid line next to Realized, and
subtract them in `_stop_exit_pnl_json`; (c) surface "T/P target distance" and consider an
operator-gated baseline re-arm rule.

### 3. No alert path for safety events — only BUY signals page anyone  [CONFIRMED]
The alerter (sound → notify-send → Telegram) fires **only** on confirmed BUYs, and Telegram env
vars aren't set. "position may be UNPROTECTED" (executor.py:1263), reconcile mismatches, T/P
flatten events, WS outages, margin-level descent — all are log/journal lines on a machine
nobody is watching at 3am. The 12h-offline incident (2026-07-12) is precedent.

**Fix shape:** set the two Telegram env vars, add an `alerter.fire_safety()` used by the
UNPROTECTED path, reconcile mismatch, T/P cycle, ml threshold, and link-down watchdog.

## CRITICAL / MAJOR findings by layer (verified unless tagged PLAUSIBLE)

### Money path (executor)
- **[M] Flatten-window race** (agent M2, mechanism verified): an entry filling during
  `_flatten_all`'s window gets market-closed by the flatten (sized from live volume), then
  promoted to 'open' by the next poll → rests a stop against nothing → naked short if it
  triggers. Narrow window; small fix (re-snapshot pendings after the OpenPositions read, or
  refuse promotion of rows whose ts falls in the flatten window).
- **[M] Reprotect starvation during incomplete flatten** (verified, executor.py:437):
  `_check_take_profit()` returning True (incl. the *incomplete* path) early-returns before
  `_reprotect_naked_open`. By then CancelAll swept ALL stops; blocked pairs sit naked for the
  whole retry period — which is longest exactly when the Kraken API is degraded. One-line fix:
  reprotect before the early return.
- **[M] `CancelAll` is account-wide** (verified, executor.py:716): sweeps manual/other-system
  orders too, and any Kraken position with no DB row loses its stop forever (flatten closes
  only DB-known pairs; reprotect only re-arms DB rows). Use CancelOrderBatch on known txids,
  or confirm the account is exclusively DEEPFIELD's.
- **[M] No `mode='live'` filter on status-driven queries** (verified pattern; latent): paper
  rows in this DB would consume the reconcile volume budget and get real stops canceled.
  One env-var flip away. Add `AND mode='live'` to the money-path queries.
- **[m] No realized P&L recorded on T/P flatten closes** ('error=tp-flatten' text rows are
  skipped by `realized_pnl_since`) — the strategy's entire realized upside is invisible to
  day/week readouts.
- **[m] Ceiling collision** (agent claimed MAJOR; my recomputation downgrades): seeds/rungs
  (conviction 1x) carry SIZE_MULT=3 in notional but not in the ceiling → refuse when
  3×min > $50. Trip prices are ~4–5× current (ADA $0.83, DOGE $0.33, SUI $3.33) — real but
  not imminent. Scale the ceiling by SIZE_MULT or lift it.
- **[m] Orders-cap headroom unmeasured** (PLAUSIBLE): ~84 resting orders and growing; a
  cap-refused stop is a naked fill whose retry also gets refused. Verify account tier cap.

### State coherence (reconcile/startup/broker)
- **[M] "all_ok" is weaker than it looks** (verified): per-pair ok = "no stop query UNKNOWN",
  not "exchange volume == ledger volume"; the startup 74=74 line is count-only cosmetics;
  surplus/untracked exchange volume is silently discarded (leftover budget never examined).
- **[M] No `userref` on any order** (verified — zero hits repo-wide): an AddOrder that errors
  ambiguously is recorded 'rejected'; if it actually landed it can never be re-identified —
  untracked position, no stop, invisible to reconcile (which has no surplus check). Send a
  userref on every AddOrder; treat surplus pair volume as loud all_ok=false.
- **[M] Identity-less volume budgeting can retire the WRONG row** (PLAUSIBLE, code-supported):
  a dead naked row (stop_txid NULL) consumes the budget first (oldest-first), the live row's
  real stop gets canceled + row closed, then a new stop rests at the dead row's stale price.
  Store Kraken posids on rows to kill the whole class.
- **[M] Stop adoption has no volume/price sanity bound** (verified mechanism): closest-volume
  match accepts arbitrarily distant stops → over-sized adopted stop sells more than the
  position on trigger. Add |vol−want|/want tolerance + price window.
- **[M] Re-placed stops use the stored price unconditionally** (PLAUSIBLE): after a gap below
  the stop while down, the re-place either instant-executes or fail-loops. Clamp against live.
- **[m] Fill promotion keeps limit price as `entry`** (never reads avg fill price) — P&L,
  ladder anchor, own-level dedupe all keyed to intended not actual price.
- **[m] Nonce persist failure is a silent `pass`** (broker.py:96) — disk-full today + clock
  step at next boot wedges all private calls with no warning logged.

### Data/signal path
- **[M] Weekly closes evaluate on a STALE weekly series** (verified, ingest.py:108-138):
  weekly bars are epoch-anchored so every weekly border coincides with a daily border; the
  Thursday double-fire fix dedups on the close INSTANT per symbol, so exactly one of the two
  coincident events gets fire=True — and `flip_closed` flips only that event's own bar. The
  watchdog iterates (1440, 10080), making daily-first deterministic: the fire=True evaluation
  runs with the just-completed weekly bar still closed=0 (excluded). Six of seven signals are
  weekly-driven. Net effect: weekly-driven BUY flips are seen one daily close (~24h) late —
  or an order fires on a verdict the completed weekly bar contradicts. Fix shape: at a
  coincident border, flip BOTH intervals' bars before the single recompute (or defer the fire
  until both are confirmed closed).
- **[M] REST-confirm failure at a border still flips the bar and fires on partial data**
  (verified, ingest.py:235-262): when the clock-close watchdog can't REST-confirm (outage),
  it flips the last pre-outage partial OHLCV into "closed truth" anyway and the order path
  runs on it. Gap-heal later repairs the values — after the order stood. No data-quality gate
  exists between a flipped bar and place_entry.
- **[M] Gap-healed closes never fire** (PLAUSIBLE, code-supported): reconnect gap-heal upserts
  closed=1 directly without emitting CandleClosed, and can beat the watchdog in the ~0-20s
  post-border window — the fire is lost with no log; self-heals only at the next daily close.
- **[m] Minimum-history: current universe verified safe** — engine run on the live DB: HBAR
  (52wk) and PEPE evaluate at denom 6/required 4; the others at 7/5. The dangerous
  required=2 zone needs <21 daily bars; nothing in code enforces a history floor — it's
  operator judgment at config time (HYPE-class listings would hit sig3's broken NA guard:
  under 35 weekly bars its "histogram" is really the raw MACD line).
- **[m] A failed WS subscription permanently mutes a pair** (one log line, no re-subscribe,
  no alarm): tick_age=inf suppresses every confirmed fire while candles keep flowing via the
  watchdog, so the card looks alive.
- **[m] Regime label has no age stamp**: a stale BULL fails CLOSED (pauses accumulation
  indefinitely, silently) — inverting the no-blockers intent. Dormant today (BEAR).
- **[m] `engine.candle_close_age` is dead code** — the intended pre-order candle-freshness
  gate is never called; only tick age gates orders. Parity harness has no runtime caller and
  no CLI flag either (startup-only manual/test invocations).
- Checked clean: zero ts gaps daily+weekly across all 28 pairs, single weekly anchor, int-only
  timestamp comparisons, inclusive REST `since` trues up crash-time forming bars, no UTC
  leakage in the candle path.
